## 7. 独立规则与数值复现

### 7.1 手势分类

将原 `HandTrackingService.ts` 经过 TypeScript 转译，移除不参与本项的 import 后，在隔离的 VM 中调用原 `detectGesture()`。为每根手指生成 180° 或 90° 夹角，遍历全部 32 种组合。

| 伸直状态，顺序为拇 / 食 / 中 / 无名 / 小 | 实测模式 |
| --- | --- |
| `00000` 五指弯曲 | SHIELD |
| `01000` 仅食指伸直 | SHIELD |
| `11000` 手枪 | DRAGON |
| `01100` 食指和中指伸直 | DRAGON |
| `01001` 食指和小指伸直 | DAGENG |
| `11001` 加拇指的摇滚 | DAGENG |
| `01111` 四根非拇指伸直 | LOTUS |
| `11111` 全伸直 | LOTUS |
| `01010` 食指与无名指伸直 | LOTUS（兜底） |

全部结果统计：SHIELD 6 种、DRAGON 5 种、DAGENG 2 种、LOTUS 19 种。另输入 21 个重合点，结果为 SHIELD；原因是角度为 NaN 后所有“>150°”都为 false。

### 7.2 缩放、分层和轨迹

按源码循环顺序复现 600 个渲染帧的共享缩放更新：

| 剑数 | 主剑缩放 | 末剑缩放 | 实际层数 | 第 11 层剑数 | 夹在最后历史样本的剑数 |
| ---: | ---: | ---: | ---: | ---: | ---: |
| 300 | 1.545106284 | 1.500107358 | 11 | 9 | 0 |
| 500 | 1.545001865 | 1.500001884 | 11 | 9 | 126 |

600 帧是循环次数，不宣称这里测量了浏览器中的 10 秒真实时间。对于大庚缩放，前节已有实际浏览器矩阵数据交叉验证。

下面数值部分只需 Node.js，可在任意目录中重跑，不需要打开摄像头或安装项目依赖：

```bash
node --input-type=module <<'JS'
for (const n of [300, 500]) {
  let shared = 1;
  let main = 0;
  for (let frame = 0; frame < 600; frame++) {
    for (let i = 0; i < n; i++) {
      const target = i === 0 ? 6 : 1.5;
      const alpha = i === 0 ? 0.01 : 0.02;
      shared += (target - shared) * alpha;
      if (i === 0) main = shared;
    }
  }
  const perLayer = Math.floor((n - 1) / 10);
  const layers = Array.from({ length: n - 1 }, (_, j) =>
    Math.floor(j / perLayer));
  const clamped = Array.from({ length: n }, (_, i) => i)
    .filter(i => i >= 5 && Math.floor(i * 0.8) >= 299).length;
  console.log({
    swords: n,
    mainScale: main,
    lastScale: shared,
    layers: Math.max(...layers) + 1,
    finalLayerCount: layers.filter(layer => layer === 10).length,
    clampedHistorySwords: clamped,
  });
}
JS
```

该片段只是复现当前公式，不是修复实现。

## 8. 模型、WASM 与归档校验

`hand_landmarker.task` 可作为 ZIP 读取，成员为：

```text
hand_detector.tflite             2,339,878 字节
hand_landmarks_detector.tflite   5,478,949 字节
```

两份本地 SIMD WASM 资源与 npm 锁定包的同名资源进行 SHA-256 比较，均不相同。原目录中没有非 SIMD 两个文件，而锁定 SDK 包中存在这些文件；其 resolver 源码会根据 WebAssembly SIMD 能力探测选择对应文件名。

本次得到的准确结论是“当前 Chrome SIMD 路径可初始化，同时其他环境存在尚未完成验证的交付风险”，不能把资源不同直接表述为“项目无法运行”。

对 `yuanma.zip` 做文件名编码修正后，将展开目录中的 30 个有效项目文件按 SHA-256 与包内对应文件比较，全部一致。这也为确认分析过程未改变原有业务源码提供了基准。
