# 03 剑阵算法与渲染

本篇以 React 版为主。核心文件为 `R/src/components/SwordSwarm.tsx`；HTML 版对应逻辑从 `H/index.html:343` 起。

## 1. 一帧中发生什么

```text
读取目标、追踪状态、模式、轨迹
→ 确定本帧中心，维护历史路径
→ 对每一把剑计算阵型目标
→ 根据距离选择速度，计算转向和局部分离力
→ 积分位置
→ 选择朝向与缩放
→ 写剑体和光环的实例矩阵
→ 标记 instanceMatrix.needsUpdate
```

各组件还有自己的 `useFrame` 回调，分别更新相机、闪电、法阵和粒子。当前没有显式的统一帧阶段编排；如需保证“识别 → 运动 → 相机 → 特效”的严格顺序，应统一调度或显式设置帧回调优先级。

## 2. 剑模型与实例化

源码：`SwordSwarm.tsx:50`、`:410`。

一把剑由三个几何体合并：

- 四棱锥 `ConeGeometry(0.12,2.5,4)`，经压扁、旋转和平移作为剑刃。
- `BoxGeometry(0.5,0.08,0.15)` 作为剑格。
- `CylinderGeometry(0.05,0.06,0.7,6)` 作为剑柄。

业务约定剑尖朝局部 `+Z`，通过 `dummy.lookAt()` 改变方向。剑体是绿色 `MeshBasicMaterial`，不依赖场景光照生成明暗；金色光环另用一个锥形网格与叠加混合材质。

剑体和光环各使用一个 `InstancedMesh`，复用几何体和材质，分别写 N 个实例矩阵。这样剑群主体在相应渲染通道通常可以由每个 InstancedMesh 一次绘制完成；整帧还包含背景、雷电、法阵和后处理，不能称整帧只有两次 draw call。

两个实例网格均设置 `frustumCulled={false}`，避免动态分散的实例受固定包围体影响而突然消失。代价是整个剑群不会被视锥裁剪跳过。

## 3. 游龙 DRAGON

源码：`SwordSwarm.tsx:243`、`store.ts:66`。

前 5 把剑追随中心，叠加约 0.3 单位的正弦摆动。其他剑沿历史轨迹取样：

```text
pathIndex = i × 0.8
a = min(floor(pathIndex), historyLength-1)
b = min(a+1, historyLength-1)
alpha = pathIndex - floor(pathIndex)
target = lerp(history[a], history[b], alpha)
```

随后叠加正余弦扰动和三维连续扰动。名为 `simplex.noise3D` 的函数实际是三个三角函数的乘积，不是真正的 Simplex Noise 实现；使用时应理解为廉价的连续周期扰动。

历史维护包含两个动作：

1. 每个新识别视频帧，目标距离历史头部超过 0.1 时，记录目标并更新最后方向。
2. 每个渲染帧，只要在追踪且为游龙，就沿最后方向从历史头部延伸 0.3。

这使轨迹既包含真实手部样本，也包含主动预测点。手停止后仍可能继续延伸，直到之后的真实样本修正方向；渲染帧率变化还会改变单位时间内添加预测点的数量。

### 轨迹长度不足

默认历史长度为 300，但桌面有 500 把剑。第 374 把（零基索引 `i=374`）开始，`floor(i×0.8) >= 299`，后 126 把都夹到最后一个历史采样点，再靠扰动和分离力散开。移动端 N=300 时没有这个越界夹取问题。

若要让 500 把都沿有效历史展开，可按剑数计算历史容量，或将 `i/(N-1)` 映射到完整历史范围。若还要均匀间距，应进一步按轨迹弧长重采样，而不是只按样本序号取点。

## 4. 护盾 SHIELD

源码：`SwordSwarm.tsx:126`。

先用斐波那契球面分布：

```text
phi = acos(1 - 2(i+0.5)/N)
theta = π(1+√5)i
x = R·sin(phi)·cos(theta + ωt)
y = R·sin(phi)·sin(theta + ωt)
z = R·cos(phi)
```

默认 `R=18`、`ω=2.5`。接着绕 Y 轴按 `0.3t` 再旋转，x/y 叠加 0.2 单位波动。最终目标以手掌中心为球心。

优先按速度方向定向；速度过低时，以相对球心向量构造绕 Y 轴切线 `(-z,0,x)`。护盾模式的基础速度更快、转向限幅乘 3，旨在快速形成球壳。

这只是飞剑球壳，没有任何拦截判断。`ShieldOrb.tsx` 中另有半透明球体，但 `Scene` 未挂载该组件，因此当前画面不会因该文件存在就自动出现护盾球。

## 5. 莲花 LOTUS

源码：`SwordSwarm.tsx:158`。

采用黄金角在 XY 平面形成空心盘状分布：

```text
goldenAngle = π(3-√5)
u = i/(N-1)
r = 6 + (24-6)√u
theta = i·goldenAngle + 2.5t
breathe = 1 + 0.05sin(2t)
x = r·breathe·cos(theta)
y = r·breathe·sin(theta)
z = 0.2sin(2t + 0.1i)
```

剑尖沿相对中心的径向向外。它看起来像莲花或向日葵，但没有单独的多层花瓣曲面模型。

注释称“面积分布均匀”，当前带内孔的公式并不严格等面积。如果目标是半径 `rMin` 到 `rMax` 的等面积圆环，公式应为：

```text
r = sqrt(rMin² + u·(rMax²-rMin²))
```

注释还提到半径相关的差速旋转，但现有 `theta` 中没有半径项，所有剑目标使用相同角速度。

## 6. 大庚 DAGENG

源码：`SwordSwarm.tsx:201`。

第 0 把为主剑，目标位于中心上方 5 单位。其余飞剑绕主剑按同心圆柱形分布：

```text
effectiveIndex = i-1
effectiveCount = N-1
perLayer = max(1,floor(effectiveCount/10))
layer = floor(effectiveIndex/perLayer)
indexInLayer = effectiveIndex % perLayer
radius = 30 + 1.5·layer + 2
direction = layer 为偶数 ? 1 : -1
theta = 2π·indexInLayer/perLayer + 0.2t·direction
height = center.y-10 + 20·(0.5sin(13.1·effectiveIndex))
```

偶数与奇数层反向旋转；所有剑朝世界下方。设计缩放是主剑 6 倍、其他剑 1.5 倍；同时法阵淡入，雷电的尝试连接数量、距离与闪烁频率增加。

这里并没有“蓄力完成后落剑攻击”的时序状态机。高度直接由上述分布决定，“仿佛随时落下”是朝向带来的视觉暗示。

### 层数与主剑问题

`floor` 分组没有处理余数：N=500 时每层 49 把，前十层容纳 490 把，剩余 9 把落入第 11 层；N=300 时每层 29 把，同样多出 9 把第 11 层。实际最大半径因此达到 47。

缩放平滑也没有按实例存储：循环读写同一个 `meshRef.current.userData.currentScale`。每次处理普通剑都会把该状态拉回 1.5 附近，下一帧主剑只能从普通剑留下的状态开始向 6 插值。600 帧数值复现显示桌面主剑约为 1.545 倍，远未达到目标 6 倍。详见问题清单与验证记录。

## 7. 转向和位置积分

源码：`SwordSwarm.tsx:277`。

这是一套简化的目标追踪 / 到达行为，不是完整的刚体物理或 Boids 群集模拟。

```text
speed = shield ? 50 : 25
若距离 > 4，speed = 50
若距离 < 1，speed = distance × 25

desired = normalize(target-position) × speed
若距离 < 10，再将 desired 乘 distance/10
steer = desired-velocity
steer 限幅到 steerForce×delta×modeFactor
velocity += steer
position += velocity×delta
```

`modeFactor` 对护盾和莲花为 3，其余为 1。小于 1 单位时两次按距离缩小，目标附近减速比单纯线性到达更强。

分离力只比较前一把索引剑，非全体邻居搜索：计算 `position[i]-position[i-1]`，距离小于 3 时加反向推力。时间复杂度保持 O(N)，但不能保证空间上任意两剑都互不重叠。由于循环中前一把位置已经更新，这个比较也带有顺序性。

核心时间问题是 `delta` 被写死成 `1/60`。如果渲染只有 30fps，每秒只积分 30 次，静止目标下的运动推进约为设计值的一半；而阵型旋转又按真实秒数计算，所以动态目标与追赶速度之间的比例发生变化。改进时优先改用 R3F 回调提供的实际 delta，对异常长帧作上限处理，再将固定 lerp 系数改为时间相关系数，例如：

```text
alpha = 1-exp(-lambda·dt)
```

若要保留严格固定时间步长，应增加累积器与必要的子步，而不是假定每次渲染都间隔 1/60 秒。

## 8. 雷电、法阵与背景

| 模块 | 实现 | 重要边界 |
| --- | --- | --- |
| DivineLightning | 预分配 100 条线段；随机选飞剑对，距离足够近才写入端点 | 数量是尝试次数上限，实际有效线段可更少；不是分叉电弧模拟 |
| 雷电增强 | 大庚强度缓动至 1，连接尝试从 30 到 100，最大距离从 5 到 25 | 隐藏还要求失去追踪或未满足闪烁条件 |
| MagicCircle | 平面 + 自定义 GLSL，以 UV 距离生成圆环、角度正弦模拟符文 | 不使用法阵贴图；可见条件为大庚且追踪成功 |
| 法阵位置 | 目标 y 上方 15，平面旋转到近水平，缩放 40 | 与主剑及外层环阵尺寸不是同一个参数 |
| StarField | 2000 个点，分布在半径 80～120 的球壳 | 一组 Points；随时间缓慢绕 Y 旋转 |
| SpiritParticles | 200 个点，逐帧改变 y 并回绕 | 增量未乘真实 dt，也存在帧率依赖 |
| Bloom | 阈值 0.1、强度 2.0、mipmapBlur | 多通道后处理，需要额外 GPU 成本 |

场景还设置深色背景与雾。云雾和远山只是保留的注释代码，没有运行。法阵中的“符文”来自角度正弦，不是文字或真实符箓字形。

## 9. 相机

源码：`R/src/components/CameraController.tsx:26`。

每帧遍历位置数组，得到平均中心、X/Y 最小最大值和跨度：

```text
formationSize = max(spanX,spanY)
targetZoom = clamp(formationSize×1.2 + 18, 22, DAGENG ? 55 : 75)
```

相机位置与注视点使用多层固定 0.02 插值。追踪时跟随剑阵平均中心；无手时跟随正弦漂移的虚拟点。相机只轻微跟随 x/y，并把注视点 z 固定为 4。

该构图方法没有显式使用屏幕纵横比、视野角、Z 范围或缩放后的剑体尺寸。虽然 Canvas 会适配尺寸，算法本身不能保证竖屏完整容纳大庚外层环阵。大庚上限 55 还小于其他模式的 75，优先服务压迫感，并非严格的包围体适配。

原说明中的“竖屏自动拉远镜头”与现有源码不完全一致：有横屏提示浮层，但相机控制器没有根据横竖屏切换独立距离。

## 10. 调参入口与影响

| 参数 / 位置 | 默认值 | 修改时需要联动考虑 |
| --- | --- | --- |
| `CONFIG.swordCount` | 移动 300 / 桌面 500 | CPU 循环、矩阵上传、轨迹长度、分层余数 |
| `CONFIG.pathHistoryLength` | 300 | 游龙尾部取样范围和历史维护成本 |
| `CONFIG.maxSpeed / sprintSpeed` | 25 / 50 | 阵型就位速度，先修正时间步长 |
| `CONFIG.steerForce` | 28 | 转弯速度和阵型追赶能力 |
| `CONFIG.shieldRadius` | 18 | 球壳尺寸和相机取景 |
| `CONFIG.lotusRadius` | 24 | 莲花外半径；内半径 6 仍在组件硬编码 |
| `CONFIG.dagengRadius / Height` | 30 / 20 | 大庚外圈与高度；额外半径、层距和主剑高度仍是硬编码 |
| `CONFIG.*RotateSpeed` | 护盾 / 莲花 2.5，大庚 0.2 | 目标运动速度，过快会使飞剑难以追赶 |
| HandController 的阈值 | 0.25 秒、150° | 响应速度与误识别，需要真实手势样本评估 |
| Canvas `dpr` | `[1,2]` | 屏幕像素数与后处理开销 |
| Bloom `intensity` | 2.0 | 亮度与视觉风格，不等于改变剑体真实光照 |

`formationRadius` 当前没有被业务代码读取；`dragonDensity` 也没有被读取，游龙密度使用的是组件中的硬编码 `0.8`。只修改这两个 CONFIG 值不会得到注释所暗示的效果。设备分类只在模块加载时计算，不会随窗口 resize 重新改变剑数。
