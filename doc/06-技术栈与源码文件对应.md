# 06 技术栈与源码文件对应

核对日期：2026-10-21。本文按当前目录名 `React/`、`HTML/` 分析，将“依赖已声明”“源码实际引用”“组件实际挂载”分开说明。版本取自现有 npm 锁文件，不代表查询了最新版本。

## 1. 技术栈总览

项目技术结构是 **React + TypeScript + Vite + Three.js / React Three Fiber + Zustand + MediaPipe + GLSL / WebAssembly**。其中 WebGL 和 WebAssembly 是浏览器运行能力，GLSL 是着色器语言，不是需要分别安装的业务框架。

| 层次 | 技术及锁定版本 | 主要文件 | 实际负责的事情 |
| --- | --- | --- | --- |
| 页面与组件 | React / React DOM 19.2.3 | `src/main.tsx`、`src/App.tsx`、所有 TSX 组件 | 挂载 UI、组合场景、管理组件生命周期 |

## 2. React：组织页面与控制生命周期

| 文件 | 关键使用 | 前端职责 |
| --- | --- | --- |

| [App.tsx](../React/src/App.tsx) | `useState/useEffect/useRef`，内部 UI 子组件 | 组织视频、Canvas 和界面；视频挂载后初始化识别服务 |
| [OrientationGuard.tsx](../React/src/components/OrientationGuard.tsx) | `useState/useEffect`、事件清理 | 监听方向和尺寸，展示可关闭的横屏建议浮层 |

| [Scene.tsx](../React/src/components/Scene.tsx) | `useRef/useMemo`、组件组合 | 创建背景数据，组合相机、剑群与特效 |

从实现方式看，React 主要负责“创建与组合”，逐帧变化交给 refs 和 R3F 帧回调。每把剑的位置没有进入 React `useState`，这是此项目处理数百对象连续动画的关键设计。

`App.tsx` 内部定义了 `StatusIndicator`、`UI`、`WebcamView`，它们不是三个单独的源码文件。阅读目录时应注意，UI 与摄像头初始化实际集中在 App 中。

## 3. Three.js 与 React Three Fiber：职责不同

**Three.js 提供 3D 对象与计算能力；React Three Fiber 让这些对象通过 React 组件树创建，并提供帧回调和上下文。** 同一个文件同时引用两者是正常分工。

### React Three Fiber 对应文件

| 文件 | 实际 API | 作用 |
| --- | --- | --- |
| [App.tsx](../React/src/App.tsx) | `Canvas` | 建立 3D 渲染区域，配置相机、DPR 和抗锯齿选项 |
| [HandController.tsx](../React/src/components/HandController.tsx) | `useThree`、`useFrame` | 获取相机，在新视频帧执行检测与目标映射 |
| [CameraController.tsx](../React/src/components/CameraController.tsx) | `useThree`、`useFrame` | 获取并逐帧修改相机位置和注视点 |
| [SwordSwarm.tsx](../React/src/components/SwordSwarm.tsx) | `useFrame`、`<instancedMesh>` | 每帧更新飞剑和光环的实例矩阵 |
| [Scene.tsx](../React/src/components/Scene.tsx) | `useFrame`、Three JSX | 更新星空和粒子，声明背景与环境 |
| [DivineLightning.tsx](../React/src/components/DivineLightning.tsx) | `useFrame`、`<lineSegments>` | 更新线段顶点与可见状态 |
| [MagicCircle.tsx](../React/src/components/MagicCircle.tsx) | `useFrame`、`<shaderMaterial>` | 更新法阵位置、透明度与时间 uniform |
| [ShieldOrb.tsx](../React/src/components/ShieldOrb.tsx) | `useFrame`、`<primitive>` | 保留的护盾球体实现，当前没有挂入 Scene |

`useFrame/useThree` 使用依赖 Canvas 提供的渲染上下文，因此 HandController 放在 Canvas 内；HTML video 则放在 Canvas 外，由普通 React DOM 管理。

### Three.js 对应文件

| 文件 | 核心对象 / 方法 | 源码价值 |
| --- | --- | --- |
| [SwordSwarm.tsx](../React/src/components/SwordSwarm.tsx) | `Vector3`、`Object3D`、基础 Geometry、`MeshBasicMaterial`、实例矩阵；`mergeGeometries` 工具 | 剑模型程序化生成、四种阵型、转向和规模化绘制的核心 |
| [HandController.tsx](../React/src/components/HandController.tsx) | `Vector3.unproject`、向量运算 | 将手部归一化坐标转换为世界 z=0 平面上的点 |
| [CameraController.tsx](../React/src/components/CameraController.tsx) | `Vector3`、`MathUtils.lerp/clamp` | 由剑群中心和跨度计算跟随视角 |
| [DivineLightning.tsx](../React/src/components/DivineLightning.tsx) | `BufferGeometry`、`BufferAttribute`、`LineBasicMaterial` | 复用顶点缓冲，生成剑间闪电线段 |
| [MagicCircle.tsx](../React/src/components/MagicCircle.tsx) | `ShaderMaterial` 类型、混合与双面设置 | 使用自定义 GPU 着色器渲染法阵 |

`<mesh>`、`<points>`、`<bufferGeometry>` 等小写 JSX 是 R3F 场景元素，不是 HTML 标签，也不是项目中漏掉的同名 React 组件文件。

## 4. Zustand：连接识别与渲染

唯一的 store 定义文件是 [src/store.ts](../React/src/store.ts)，由 `create<HandState>()` 创建。

| 角色 | 文件 | 数据流 |
| --- | --- | --- |
| 定义状态与动作 | `store.ts` | CONFIG、GestureMode、HandState、状态与轨迹方法 |
| 生产手部输入 | `HandController.tsx` | 写入 targetPosition、isTracking、gestureMode；记录游龙路径 |
| 消费并维护轨迹 | `SwordSwarm.tsx` | 逐帧读状态，游龙时调用 extendPath，待机时维护历史 |
| 消费 UI 状态 | `App.tsx` | selector 订阅模式与追踪状态 |
| 消费相机状态 | `CameraController.tsx` | 逐帧读取模式和追踪状态 |
| 消费特效状态 | `DivineLightning.tsx`、`MagicCircle.tsx` | 控制闪电和法阵的表现 |
| 保留消费者 | `ShieldOrb.tsx` | 有状态读取实现，但当前组件未挂载 |

这里没有 Redux、React Context 自建状态方案或后端状态同步。Zustand 既承载交互状态，也放置了部分可变 Three 对象。后续维护时要区分 selector 驱动的界面更新和 `getState()` 驱动的逐帧读取：原地修改轨迹数组不会自动等同于发布一次新的状态变更。

## 5. MediaPipe、WASM 与原生摄像头

| 文件 / 资源 | 类型 | 负责内容 |
| --- | --- | --- |
| [HandTrackingService.ts](../React/src/services/HandTrackingService.ts) | 自有 TypeScript 服务 | 调用摄像头 API、加载 FilesetResolver 与 HandLandmarker、提供规则分类函数 |
| [HandController.tsx](../React/src/components/HandController.tsx) | 自有 React 控制组件 | 每个新视频帧调用 `detectForVideo`，确认手势，投影目标位置 |
| [App.tsx](../React/src/App.tsx) 的 WebcamView | DOM 视频与生命周期 | 提供可播放的视频元素，并触发服务初始化 |
| [hand_landmarker.task](../React/public/models/hand_landmarker.task) | 二进制模型包 | 包含手检测和关键点检测模型 |
| [vision_wasm_internal.js](../React/public/models/wasm/vision_wasm_internal.js) | 第三方生成的 JS | WASM 运行时加载与桥接；不是手写业务逻辑 |
| [vision_wasm_internal.wasm](../React/public/models/wasm/vision_wasm_internal.wasm) | WebAssembly 二进制 | 推理运行时计算资源 |

调用关系：

```text
WebcamView 挂载
→ initHandTracking(video)
→ getUserMedia → video.srcObject
→ FilesetResolver → HandLandmarker.createFromOptions
→ HandController.detectForVideo(video, timestamp)
→ detectGesture(landmarks)
→ 250ms 手势确认 → Zustand → 阵型与特效
```

MediaPipe 负责“从图像得到手部关键点”，自有 `detectGesture` 负责“根据关节夹角选择技能”。后者没有使用 MediaPipe 的 GestureRecognizer，也没有单独的技能分类模型。

`public/models/` 是需要交付的运行资源，不能因为它位于 public 就当作模板文件删除。它与 `public/vite.svg` 的重要程度完全不同。

原生浏览器 API 的其他落点：`HandTrackingService.ts` 使用 MediaDevices / video；`OrientationGuard.tsx` 使用屏幕方向、媒体查询和 resize 事件；`store.ts` 直接读取 navigator 与 window 进行设备判定；`HandController.tsx` 使用 `performance.now()` 作为推理时间戳。`window.swordPositions` 则是自有全局共享引用，不属于 Zustand。

## 6. 后处理、GLSL 与样式

### 后处理

[Scene.tsx](../React/src/components/Scene.tsx) 直接从 `@react-three/postprocessing` 引入 `EffectComposer` 和 `Bloom`。`postprocessing` 是其底层效果库，当前自有 `src/` 没有直接 import 它。

这意味着不能把“没有直接 import postprocessing”认定为“该依赖没用”。React 封装层和底层效果库是同一链路的不同层次。

### 自定义着色器

[MagicCircle.tsx](../React/src/components/MagicCircle.tsx) 内嵌 `vertexShader` 和 `fragmentShader` 字符串，通过 `<shaderMaterial>` 使用。顶点部分传递 UV 并计算投影，片元部分利用 UV 距离和角度构造圆环与符文效果，`uTime/uOpacity` 由帧回调更新。

项目没有独立 `.glsl` 文件，没有法阵贴图，也没有引入专用 Shader 构建插件。调整法阵图案应优先读这个文件，而非寻找静态图片。

### CSS

| 文件 | 使用状态 | 作用 |
| --- | --- | --- |
| [src/index.css](../React/src/index.css) | `main.tsx` 与 `App.tsx` 均引入 | 全局 margin/padding、全屏 root、字体、背景与溢出控制 |
| `App.tsx` 中 style 对象 | 生效 | 状态标签、底部提示、视频位置与外观 |
| `OrientationGuard.tsx` 中 style 对象 | 条件生效 | 横屏提示浮层及按钮 |
| [src/App.css](../React/src/App.css) | 未被当前入口 import | Vite 模板样式，不能把其中 root 最大宽度当作当前布局约束 |

当前没有 Tailwind、Sass、CSS Modules、Ant Design 或其他现成 UI 组件库的业务引用。

生产构建链路为：

```text
npm run build
→ tsc -b：按 project references 执行类型检查（noEmit）
→ vite build：转换并打包业务源码
→ dist/index.html + assets + public 中的静态资源
```

`tsc -b` 没有在 src 旁生成业务 JS 文件；实际交付的 JS 来自 Vite 构建。开发服务可以正常启动也不等于类型检查已通过，所以不能省略构建中的 `tsc -b`。

`@types/react`、`@types/react-dom`、`@types/three` 和 `@types/node` 是类型定义，不是额外的页面运行模块。`@types/three` 虽被列在 dependencies，其主要职责仍是 TypeScript 类型支持。

## 9. HTML 版：相同技术的单文件落点

[HTML/index.html](../HTML/index.html) 中集中了原本分散的模块，但没有使用 React 版的本地 Vite / TypeScript 构建链。

| 技术 / 模块 | HTML 中的位置 | 与 React 版的区别 |
| --- | --- | --- |
| Babel standalone | 第 18 行脚本 | 浏览器内转换 JSX，React 版通过构建工具处理 |
| ES Modules / import map | 第 21 行起 | 从 CDN 解析 React、Three 等库，版本与 React 版不同 |
| Zustand 状态 | 第 102 行附近的 store 段 | 无单独 store.ts 文件 |
| MediaPipe 服务 | 第 181 行附近 | WASM 和模型改为远程地址 |
| SwordSwarm | 第 343 行 | 剑群实现集中在同一 script 中 |
| 雷电 / 法阵 / 护盾球 | 第 745 / 863 / 931 行 | 组件函数仍保留，是否生效取决于 Scene 挂载 |
| 相机 / 背景 / Scene | 第 1020 / 1117 / 1169 / 1221 行 | 无单独组件文件 |
| HandController | 第 1255 行 | 推理结果处理、确认与投影逻辑 |
| OrientationGuard | 第 1340 行 | 横屏建议浮层 |
| 状态 UI / 提示 / 视频 / App | 第 1474 / 1555 / 1625 / 1661 行 | 额外加入初始化错误轮询与演示模式提示 |
| CSS | head 内 style | 不再通过 src/index.css 模块导入 |

HTML 版的业务依然基于 React 和 R3F，并非直接手写 `new WebGLRenderer()` 的原生 Three.js 页面。单 HTML 文件也不表示离线独立运行，它还依赖 CDN JS、WASM 和模型。
